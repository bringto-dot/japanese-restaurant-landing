# タコとハイボール — Tako to Highball

![HTML5](https://img.shields.io/badge/HTML5-E34F26?style=flat-square&logo=html5&logoColor=white) ![CSS3](https://img.shields.io/badge/CSS3-1572B6?style=flat-square&logo=css3&logoColor=white) ![JavaScript](https://img.shields.io/badge/JavaScript-F7DF1E?style=flat-square&logo=javascript&logoColor=black)

**[Живая версия](https://bringto-dot.github.io/japanese-restaurant-landing/)**

Концептуальный landing page для японского ресторана, построенный вокруг
темной editorial-визуальной стилистики, кинематографичных медиа и сдержанной
типографики.

Цель проекта заключалась в создании сайта ресторана, который воспринимается
скорее как презентация премиального бренда, чем как стандартный ресторанный
шаблон.

## Обзор

Tako to Highball — вымышленный японский ресторан на четырнадцать посадочных
мест.

Страница была разработана как полноценный frontend-концепт с особым
вниманием к:

- визуальной композиции и типографике
- адаптивным layout-решениям
- кинематографичной работе с изображениями и видео
- scroll-based анимациям
- мультиязычному контенту
- сценарию бронирования
- загрузке медиа и производительности

Ресторан, меню, шеф и коммерческие данные являются вымышленными и были
созданы специально для этого концепта.

## Превью

![Hero](docs/preview/01-hero.jpg)

Визуальное направление намеренно сдержанное: темные поверхности, теплая
фотография, японская типографика и единственный красный акцент создают
визуальную идентичность страницы без использования декоративных
UI-элементов.

Hero сразу задает атмосферу, сохраняя основные действия и необходимую
информацию читаемыми поверх фотографии.

## Визуальное направление

Интерфейс сочетает serif-типографику для крупных заголовков и нейтральный
grotesk для вспомогательной информации.

Крупные editorial-заголовки создают иерархию, а небольшие uppercase-метки,
тонкие разделители и большое количество свободного пространства сохраняют
интерфейс спокойным и структурированным.

Вместо повторения одного и того же layout для всей страницы каждая секция
имеет собственную композицию.

В результате страница воспринимается как единое визуальное повествование, а
не как набор независимых блоков.

## Меню

![Меню](docs/preview/02-menu.jpg)

Раздел меню использует трехколоночную editorial-композицию для представления
основных блюд.

Каждый элемент объединяет фотографию, типографику, цену и короткое описание,
не превращая контент в обычные ресторанные карточки.

Hover-взаимодействие добавляет легкое масштабирование изображения и
изменение насыщенности, делая интерактивность заметной, но сохраняя
визуальную сдержанность секции.

## Анимации и медиа

![Хайбол](docs/preview/03-highball.jpg)

Анимации используются для управления ритмом страницы, а не просто для ее
украшения.

Изображения и видео появляются через shutter-переход с одновременным
небольшим масштабированием. Заголовки появляются через маску, а между
отдельными элементами используются небольшие задержки.

Страница также использует видео непосредственно как часть layout:
полноэкранные медиа-секции и sticky-секция с шефом делают фотографию и
движение частью композиции, а не второстепенными элементами.

Все reveal-анимации реализованы с помощью CSS и `IntersectionObserver`.

Для браузеров или пользователей, которым недоступны необходимые возможности
анимации, интерфейс переходит к статичной подаче. Также учитывается
`prefers-reduced-motion`.

## Секция шефа

![Шеф](docs/preview/04-chef.jpg)

Секция шефа использует split-layout с постоянно отображаемым видео с одной
стороны и прокручиваемым editorial-контентом с другой.

На десктопе медиа остается зафиксированным, пока контент последовательно
прокручивается рядом с ним. На небольших экранах layout переключается на
обычную вертикальную структуру.

Эта секция была создана специально для демонстрации того, как длинный
контентный блок можно сделать визуально выразительным без заполнения
страницы дополнительными UI-элементами.

## Бронирование

![Бронь](docs/preview/05-reservation.jpg)

Финальная секция переводит визуальную презентацию в простой сценарий
бронирования.

Форма включает:

- выбор даты
- выбор времени
- количество гостей
- имя
- телефон
- email
- дополнительный комментарий

Клиентская валидация предотвращает отправку незаполненной формы и выбор
прошедших дат. После корректной отправки форма переходит в состояние
подтверждения.

В этом концепте форма работает только на frontend. Данные бронирования не
отправляются на реальный backend.

## Адаптивность

Layout был разработан для desktop, tablet и mobile, а не просто уменьшен с
десктопной версии.

На небольших экранах:

- desktop-навигация превращается в компактное мобильное меню
- трехколоночное меню переходит в одну колонку
- split-screen секция шефа превращается в вертикальную последовательность
- форма бронирования перестраивает свои поля
- информационные сетки переходят в читаемую одноколоночную структуру
- полноэкранные медиа-секции адаптируют свое позиционирование и overlays

Визуальная иерархия сохраняется, а композиция меняется в соответствии с
доступным пространством.

## Два языка

Сайт поддерживает английский и русский языки в рамках одного frontend.

Контент обеих версий хранится непосредственно в разметке и переключается во
время работы страницы. Выбранный язык сохраняется между посещениями через
`localStorage`.

Типографика и отступы также учитывают оба языка, чтобы переключение между
ними не меняло общую композицию.

## Frontend

Проект намеренно создан без frontend-фреймворка или UI-библиотеки.

HTML · CSS · JavaScript

Реализация использует нативные возможности браузера для:

- responsive CSS layouts
- CSS transitions и animations
- `IntersectionObserver`
- `animation-timeline` в поддерживаемых браузерах
- native form validation
- lazy loading видео
- сохранения выбранного языка на клиенте

Проект не требует build system или внешних frontend-зависимостей.

## Производительность

Страница активно использует медиа, поэтому для сохранения
производительности применено несколько подходов:

- сразу загружается только hero image
- видео ниже первого экрана подключаются при приближении соответствующей
  секции к viewport
- видео отключают звук и оптимизированы для фонового воспроизведения
- изображения используют lazy loading там, где это необходимо
- анимации отключаются для пользователей, предпочитающих reduced motion

Визуальный результат намеренно насыщен медиа, поэтому производительность
была частью реализации с самого начала, а не задачей, которую нужно было
решать после завершения интерфейса.

## Примечания к проекту

Это вымышленный концепт ресторана, созданный как frontend-портфолио проект.

Название ресторана, шеф, меню, цены, адрес и данные для бронирования
являются вымышленными. Фотографии в интерфейсе используются как визуальный
контент для концепта.

Форма бронирования демонстрирует полноценный frontend-сценарий
взаимодействия, но не подключена к реальному сервису бронирования или
backend.
